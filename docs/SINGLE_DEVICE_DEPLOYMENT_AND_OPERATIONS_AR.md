# دليل التثبيت والتشغيل الإنتاجي على جهاز المحل الواحد (Windows)

هذا الدليل مخصص لتثبيت وتشغيل **رَفّ | RetailOS** على **جهاز كمبيوتر واحد داخل المحل** بقاعدة بيانات SQLite محلية، مع ربط الخادم بعنوان `127.0.0.1:4173` فقط (بدون فتح منفذ على الشبكة المحلية أو الإنترنت).

---

## 1. المتطلبات المسبقة للجهاز المستهدف

- نظام **Windows 10 / Windows 11** محدث ومفعل عليه **Microsoft Defender** و**BitLocker** (أو تشفير الجهاز) وقفل شاشة تلقائي.
- حساب مستخدم Windows عادي (**Standard User** — ليس Administrator) لتشغيل نقطة البيع اليومية.
- **Node.js `>= 22.0.0` LTS** و **pnpm `>= 10.0.0`** (لتجهيز وتحديث الحزمة).

---

## 2. خطوات التثبيت والتجهيز لأول مرة (بدون تفاعل)

نفّذ الأوامر التالية في PowerShell كمجهّز/فني الإعداد في مجلد المشروع:

```powershell
pnpm install --frozen-lockfile
pnpm run build
```

> لا تضع أي كلمات مرور أو عبارات سرية للنسخ الاحتياطي داخل ملفات المشروع أو البيئة الدائمة.

### تحديد مسار البيانات الآمن (`RETAILOS_DATA_DIR`)
افتراضيًا تُحفظ القاعدة في `apps/web/data/retailos.sqlite`. لتخزينها في مسار مستقل أو قرص محمي (مثال `D:\RetailOS-Data`):

```powershell
[Environment]::SetEnvironmentVariable("RETAILOS_DATA_DIR", "D:\RetailOS-Data", "User")
```

### تثبيت اختصارات سطح المكتب والتشغيل التلقائي مع الويندوز

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\install-shop-launcher.ps1 -RegisterAutoStart
```

هذا الأمر يُنشئ:
1. أيقونة على سطح المكتب: **`تشغيل رَفّ - RetailOS`** (تبدأ السيرفر محليًا في الخلفية بدون نافذة أوامر سوداء وتفتح `http://127.0.0.1:4173`).
2. أيقونة على سطح المكتب: **`إيقاف رَفّ - RetailOS`** (تُغلق الخادم بنظام وتنفّذ فحص SQLite WAL والنسخة الاحتياطية اليومية قبل الإغلاق).
3. اختصار تشغيل تلقائي عند تسجيل دخول المستخدم (`Startup\RetailOS-AutoStart.lnk`) لبدء الخدمة تلقائيًا بعد إعادة تشغيل الجهاز.

---

## 3. سياسة النسخ الاحتياطي الخارجي والاستعادة

1. **الوجهة الخارجية (إلزامي قبل الاعتماد اليومي):**
   - من داخل البرنامج ← **النسخ الاحتياطي اليومي والاستعادة** ← اختر مجلدًا خارج قرص النظام `C:` مثل:
     - فلاشة USB مخصصة، أو
     - قرص/بارتشن آخر (`D:\RetailOS-Backups`)، أو
     - مجلد متزامن سحابيًا (`OneDrive` / `Google Drive`).
2. **الاحتفاظ (Retention):**
   - يحتفظ النظام محليًا بـ **30 نسخة يومية** + مزامنة خارجية تلقائية عند العمل وعند الإغلاق.
   - أسبوعيًا: صدّر **نسخة مشفرة (`.rfbackup`)** بكلمة مرور لا تقل عن **12 حرفًا** واحفظها على وسيلة تخزين منفصلة لدى مالك المحل فقط (لا تحفظ كلمة المرور في ملف نصي على نفس الجهاز).
3. **اختبار الاستعادة التلقائي:**
   ```powershell
   node .\scripts\verify-backup-restore.mjs
   ```
4. **خطوات الاستعادة الفعلية عند تعطل القرص أو تلف القاعدة:**
   - ثبّت Node.js والمشروع على الجهاز البديل، شغّل التطبيق، أكمل الإعداد بنفس إعدادات الشركة (`RETAILOS_COMPANY_CODE` و`RETAILOS_CURRENCY`).
   - ادخل من صفحة **النسخ الاحتياطي** ← **استعادة نسخة مشفرة** ← ارفع ملف `.rfbackup` وأدخل كلمة المرور السرية.
   - يحفظ النظام نسخة أمان فورية (`backups/pre-restore/`) ثم يستبدل القاعدة ذريًا ويعيد تشغيل الخادم تلقائيًا.

---

## 4. سياسة التحديث والترحيل الآمن

قبل تطبيق أي تحديث للكود:
1. أوقف التشغيل عبر **`إيقاف رَفّ - RetailOS`** أو نفّذ نسخة احتياطية مشفرة يدوية أولاً.
2. خُذ نسخة إضافية يدوية من مجلد `data\retailos.sqlite`.
3. نزّل التحديث ثم شغّل:
   ```powershell
   pnpm install --frozen-lockfile
   pnpm run build
   pnpm test
   ```
4. شغّل التطبيق وتأكد من نجاح فتح الصفحة الرئيسية ومرور `kysely_migration` بدون أخطاء.
5. **خطة الرجوع (Rollback):** في حال فشل أي خطوة، استعد النسخة المأخوذة قبل التحديث عبر صفحة الاستعادة أو استرجاع ملف القاعدة المحفوظ قبل الترقية مع النسخة البرمجية السابقة.
